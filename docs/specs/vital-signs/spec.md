# 生命徵象

> 狀態：定案

## 1. 目的

- 護理師替病患記錄體溫、心跳、呼吸、血壓、血氧，並從列表查看與修改紀錄

## 2. 需求

### REQ-VIT-001 生命徵象列表

- 列出所有病患的紀錄，記錄時間新的在最上面，每頁 20 筆

- **AC1 列出紀錄**〔後端、E2E〕：Given 已有紀錄 When 開啟生命徵象列表 Then 顯示病歷號、姓名、記錄時間、體溫、心跳、呼吸、血壓、血氧，記錄時間新的在最上面
- **AC2 分頁**〔後端、E2E〕：Given 紀錄超過 20 筆 When 開啟生命徵象列表 Then 每頁顯示 20 筆與總筆數，可以換到其他頁
- **AC3 沒有紀錄**〔E2E〕：Given 沒有任何紀錄 When 開啟生命徵象列表 Then 顯示「目前沒有紀錄」

### REQ-VIT-002 搜尋紀錄

- 輸入病歷號或姓名的一部分，列出符合的病患的紀錄

- **AC1 病歷號或姓名部分符合**〔後端、E2E〕：Given 有病患 A001 陳測試、B002 林範例的紀錄 When 搜尋「a00」 Then 只列出 A001 的紀錄；搜尋「林」 Then 只列出 B002 的紀錄
- **AC2 找不到**〔E2E〕：Given 沒有符合的紀錄 When 搜尋 Then 顯示「找不到符合的紀錄」

### REQ-VIT-003 新增紀錄

- 在對話框選擇病患，輸入記錄時間與各項數值後新增

- **AC1 新增成功**〔後端、E2E〕：Given 已搜尋或在其他頁 When 選擇病患、用預設的記錄時間並輸入各項數值後送出 Then 關閉對話框，清除搜尋並回到第 1 頁，新紀錄在最上面
- **AC2 記錄時間預設為現在**〔E2E〕：When 開啟新增對話框 Then 記錄時間是現在的日期與時間
- **AC3 選擇病患**〔後端、E2E〕：When 在病患欄輸入病歷號或姓名的一部分 Then 依病歷號由小到大列出符合的病患，最多 20 位；超過 20 位時，選單最下面顯示「符合的病患超過 20 位，請輸入更多字」；選擇後顯示病歷號與姓名
- **AC4 欄位空白**〔後端、E2E〕：When 沒選病患，或記錄時間、任一項數值沒填就送出 Then 該欄位顯示必填提示，不送出；不經畫面直接送出時被拒絕
- **AC5 數值格式**〔後端、E2E〕：When 數值是負數、超過位數上限、體溫超過 1 位小數，或其他項目有小數 Then 該欄位顯示訊息，不送出；不經畫面直接送出時被拒絕。訊息：負數或超過位數上限時「〇〇需介於 0～999」（體溫是「體溫需介於 0～999.9」）；體溫超過 1 位小數時「體溫最多 1 位小數」；其他項目有小數時「〇〇只能是整數」
- **AC6 記錄時間不能是未來**〔後端、E2E〕：When 記錄時間晚於現在 Then 記錄時間欄顯示「記錄時間不能晚於現在」，不送出；不經畫面直接送出時被拒絕
- **AC7 同一時間已有紀錄**〔後端、E2E〕：Given 病患 A001 在 2026-11-05 08:00 已有紀錄（包含已刪除的紀錄）When 新增 A001 在 2026-11-05 08:00 的紀錄 Then 記錄時間欄顯示「這個時間已經有紀錄」，不新增

### REQ-VIT-004 編輯紀錄

- 可以修改記錄時間與各項數值，不能更換病患

- **AC1 編輯成功**〔後端、E2E〕：Given 已搜尋並在第 2 頁 When 修改紀錄後送出 Then 關閉對話框，停在原本的搜尋條件與頁碼，列表顯示修改後的值
- **AC2 不能更換病患**〔後端、E2E〕：When 開啟編輯對話框 Then 病患只顯示病歷號與姓名，不能修改；不經畫面直接送出時也無法更換病患
- **AC3 欄位檢查**〔後端〕：When 編輯時送出空白、格式不符或晚於現在的資料 Then 被拒絕，規則同 REQ-VIT-003 AC4～AC6
- **AC4 改成已有紀錄的時間**〔後端、E2E〕：Given 同一位病患在 08:00 與 12:00 各有一筆紀錄 When 把 12:00 那筆改成 08:00 Then 記錄時間欄顯示「這個時間已經有紀錄」，不修改

## 3. API

| 方法 | 路徑 | 用途 | 對應 REQ |
|---|---|---|---|
| GET | `/api/vital-signs` | 生命徵象列表、搜尋紀錄 | VIT-001、VIT-002 |
| POST | `/api/vital-signs` | 新增紀錄 | VIT-003 |
| PUT | `/api/vital-signs/{id}` | 編輯紀錄 | VIT-004 |
| GET | `/api/vital-signs/patient-options` | 新增紀錄時，用病歷號或姓名搜尋病患 | VIT-003 |

- 分頁的參數與回應格式見 [conventions.md](../../conventions.md) §1.9

│ A001    陳測試  2026-11-05 12:00  36.8    78    16  122/78     98  [編輯] │

- 手機上「新增紀錄」放在搜尋框上方、靠右；每筆紀錄改成一張卡片，樣子看 `/design-system` 頁

| 編輯 | `Button` | — | — | 開啟這筆紀錄的編輯對話框 |

- 版型：對話框，標題是「新增紀錄」或「編輯紀錄」
- 入口：生命徵象列表的「新增紀錄」、每筆紀錄的「編輯」

```
┌──────────────────────────────────────┐
│ 新增紀錄                           ✕ │
│  ┌──────────────────────────────┐    │
│  │ ⚠ 請修正標示的欄位            │    │  ← FormAlert，有錯時才顯示

│  病患                                │
│  [🔍 輸入病歷號或姓名          ▾]    │  ← 編輯時改成文字「A001　陳測試」
│  記錄時間                            │
│  [2026-11-05 12:00              ]    │
│  體溫（°C）        心跳（次/分）     │
│  [        ]        [        ]        │
│  呼吸（次/分）     血氧（%）         │
│  [        ]        [        ]        │
│  收縮壓（mmHg）    舒張壓（mmHg）    │
│  [        ]        [        ]        │
│                      [取消] [儲存]   │
└──────────────────────────────────────┘
```

#### 欄位

| 欄位 | 類型 | 必填 | 限制 | 行為 |
|---|---|---|---|---|
| 病患 | `ComboboxField` | 是 | — | 邊輸入邊查詢，停止輸入 0.3 秒後才送出；列出符合的病患（REQ-VIT-003 AC3）；編輯時只顯示，不能修改（REQ-VIT-004 AC2） |
| 記錄時間 | `DateTimeField` | 是 | 到分鐘，不能晚於現在（REQ-VIT-003 AC6） | 新增時預設為現在（REQ-VIT-003 AC2） |
| 體溫 | `NumberField` | 是 | 0～999.9，最多 1 位小數（REQ-VIT-003 AC5） | — |
| 心跳 | `NumberField` | 是 | 0～999 的整數（REQ-VIT-003 AC5） | — |
| 呼吸 | `NumberField` | 是 | 0～999 的整數（REQ-VIT-003 AC5） | — |
| 收縮壓 | `NumberField` | 是 | 0～999 的整數（REQ-VIT-003 AC5） | — |
| 舒張壓 | `NumberField` | 是 | 0～999 的整數（REQ-VIT-003 AC5） | — |
| 血氧 | `NumberField` | 是 | 0～999 的整數（REQ-VIT-003 AC5） | — |
| 儲存 | `SubmitButton` | — | — | — |

- 按「取消」或關閉對話框時不儲存；再次開啟新增對話框時欄位是空的，記錄時間是現在

## 5. 做法

- 數值只檢查必填、格式、不能是負數與位數上限，不檢查醫學上的合理範圍：範圍要由臨床人員確認，訂錯會讓真實的數值記不進去
- 記錄時間只到分鐘，存入前把秒數歸零：同一分鐘的兩筆才會被唯一約束擋下
- 「不能晚於現在」用注入的 `Clock` 判斷，見 [conventions.md](../../conventions.md) §1.8
- 編輯的請求不含病患：從 API 就無法更換病患
- 選擇病患用生命徵象自己的 API，不共用病患列表的 API：之後依權限控管時，兩邊可以分開
- 選擇病患的 API 不分頁，最多回 20 位，並回傳是否還有更多：選單裡換頁不好操作，多輸入幾個字縮小範圍比較快
- 搜尋時病歷號轉成大寫後部分符合，姓名直接部分符合，兩者符合其一就列出
- 排序依記錄時間由新到舊，相同時再依 `id`：時間相同的資料換頁時才不會重複或漏掉
